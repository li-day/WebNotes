# 前端技术问题汇总

## 请求与响应处理
1. **批量请求失败只弹出一个toast**
   - 可通过设置一个标志位控制toast显示状态，如使用Promise.allSettled()监听所有请求状态，当检测到有失败且标志位未触发时显示toast并更新标志位
   - 或使用防抖函数，在短时间内多次失败只触发一次toast

2. **如何解决页面请求接口大规模并发问题**
   - 实现请求队列，控制并发数量
   - 对相同请求进行合并，避免重复请求
   - 使用缓存策略，减少不必要的请求
   - 实现请求优先级机制，核心接口优先处理

3. **axios 是否可以取消请求**
   - 可以，通过CancelToken实现：
     ```javascript
     const source = axios.CancelToken.source();
     axios.get('/api', { cancelToken: source.token }).catch(err => {
       if (axios.isCancel(err)) { /* 处理取消 */ }
     });
     // 取消请求
     source.cancel('取消原因');
     ```

4. **封装请求超时重试代码**
   ```javascript
   function requestWithRetry(url, options = {}, retryCount = 3) {
     return axios({ ...options, url, timeout: 5000 })
       .catch(error => {
         if (retryCount > 0 && error.code === 'ECONNABORTED') {
           return requestWithRetry(url, options, retryCount - 1);
         }
         return Promise.reject(error);
       });
   }
   ```

5. **前端如何设置请求超时时间 timeout**
   - axios中可直接配置：`axios.get(url, { timeout: 5000 })`
   - 原生fetch可结合AbortController：
     ```javascript
     const controller = new AbortController();
     setTimeout(() => controller.abort(), 5000);
     fetch(url, { signal: controller.signal });
     ```

6. **如何拦截 web 应用的请求**
   - axios可通过拦截器：`axios.interceptors.request.use(config => { ... })`
   - 原生可重写XMLHttpRequest或fetch
   - 使用service worker拦截网络请求

## 浏览器与网络
1. **px 如何转为 rem**
   - 设置根元素font-size：`html { font-size: 16px; }` (1rem = 16px)
   - 计算方式：目标px值 / 根元素font-size = rem值
   - 实际开发中可使用postcss-pxtorem自动转换
   - 结合媒体查询动态调整根元素font-size实现响应式

2. **浏览器有同源策略，但是为何 cdn 请求资源的时候不会有跨域限制**
   - 同源策略主要限制脚本的跨域访问，而CDN资源(如js、css、图片)属于被动加载资源
   - 浏览器对link、script、img等标签的资源请求默认允许跨域
   - 跨域限制主要针对XMLHttpRequest、Fetch等主动请求

3. **cookie 可以实现不同域共享吗**
   - 通常不可以，cookie受域名限制
   - 特殊场景可通过以下方式实现跨域共享：
     - 父域名相同的子域名间，设置domain为父域名
     - 利用iframe+postMessage传递cookie信息
     - 服务器端中转共享

4. **cookie 构成部分有哪些**
   - name: cookie名称
   - value: cookie值
   - domain: 生效域名
   - path: 生效路径
   - expires/max-age: 过期时间
   - secure: 仅HTTPS传输
   - HttpOnly: 禁止JS访问
   - SameSite: 跨站请求控制

5. **DNS 协议了解多少**
   - DNS(Domain Name System)是域名解析系统
   - 作用：将域名转换为IP地址
   - 解析过程：本地缓存 → 本地DNS服务器 → 根域名服务器 → 顶级域名服务器 → 权威域名服务器
   - 优化方式：DNS预解析、DNS缓存

6. **HTTP是一个无状态的协议，那么Web应用要怎么保持用户的登录态呢?**
   - Cookie + Session机制
   - Token认证(JWT等)
   - 第三方认证(OAuth2.0)
   - localStorage/sessionStorage存储认证信息

7. **浏览器对队头阻塞有什么优化?**
   - HTTP/2的多路复用，多个请求共享一个TCP连接
   - 域名分片，增加并行连接数
   - 预连接(preconnect)和预加载(preload)
   - 压缩HTTP头部(HPACK)

## 前端框架与库
1. **[React]循环渲染中为什么推荐不用 index 做 key**
   - 当列表项发生增删改时，index会变化，导致React错误地复用组件
   - 可能引起组件状态混乱和不必要的重渲染
   - 推荐使用每个项唯一且稳定的标识作为key

2. **[React]如何避免使用 context 的时候，引起整个挂载节点树的重新渲染**
   - 将context拆分，避免单一context包含过多状态
   - 使用useMemo缓存context value
   - 结合useCallback缓存传递的函数
   - 拆分组件，使消费context的组件尽可能小

3. **[React]react-router和原生路由区别**
   - react-router：
     - 基于前端路由，不刷新页面
     - 声明式路由配置
     - 提供多种路由匹配方式和钩子
     - 与React组件生命周期结合
   - 原生路由：
     - 基于URL变化，会导致页面刷新
     - 服务端处理路由逻辑
     - 依赖浏览器history API

4. **[React]如何进行路由变化监听**
   - 使用useEffect监听location变化：
     ```javascript
     import { useLocation } from 'react-router-dom';
     function Component() {
       const location = useLocation();
       useEffect(() => {
         // 处理路由变化
       }, [location.pathname]);
     }
     ```
   - 使用history.listen()方法

5. **[React]如何避免不必要的渲染?**
   - 使用React.memo包裹组件
   - 使用useMemo缓存计算结果
   - 使用useCallback缓存函数引用
   - 合理拆分组件，避免状态集中
   - 使用shouldComponentUpdate生命周期(类组件)

6. **[Vue]中为何不要把 v-if 和 v-for 同时用在同一个元素上，原理是什么?**
   - 优先级问题：v-for优先级高于v-if
   - 性能问题：每次渲染都会遍历整个列表，再判断条件
   - 解决方式：外层用v-if，内层用v-for；或使用计算属性过滤列表

7. **vue 中 Scoped Styles 是如何实现样式隔离的，原理是啥?**
   - 通过PostCSS给HTML元素添加data-v-xxx属性
   - 对应CSS选择器也会添加该属性选择器，形成作用域隔离
   - 实现组件样式的局部作用域，防止样式污染

8. **vue-cli 都做了哪些事儿，有哪些功能?**
   - 项目脚手架搭建
   - 基于webpack的构建配置
   - 开发服务器与热更新

   - 测试环境配置

## 微前端与工程化
1. **[微前端]为何通常在微前端应用隔离，不选择 iframe 方案**
   - 缺点：
     - 通信复杂，父子页面交互成本高
     - 样式隔离难以突破
     - 性能开销较大
     - 浏览器前进后退等行为处理复杂
     - 共享资源困难

2. **[微前端]Qiankun是如何做 JS 隔离的**
   - 使用沙箱(Sandbox)机制
   - 快照沙箱：记录window状态，切换时恢复
   - 代理沙箱：通过Proxy代理window对象
   - 严格模式沙箱：使用with+eval实现独立作用域

3. **[微前端]微前端架构一般是如何做 JavaScript隔离**
   - 快照沙箱：保存和恢复执行环境
   - 代理沙箱：代理全局对象访问
   - 模块隔离：基于ES模块的作用域隔离
   - 阴影DOM：结合DOM隔离实现JS间接隔离

4. **[webpack]有哪些优化项目的手段?**
   - 代码分割：splitChunks拆分公共代码
   - 压缩优化：terser-webpack-plugin, css-minimizer-webpack-plugin
   - 缓存策略：合理设置hash，利用持久化缓存
   -  loader优化：include/exclude限制范围，使用cache-loader
   - 插件优化：tree-shaking, ModuleConcatenationPlugin
   - 资源优化：图片压缩，字体优化
   - 多进程：thread-loader, parallel-webpack

5. **[webpack]打包时 hash 码是如何生成的**
   - hash：基于整个项目内容生成，所有文件共享相同hash
   - chunkhash：基于chunk内容生成，同一chunk共享相同hash
   - contenthash：基于文件内容生成，文件内容不变则hash不变
   - 生成过程：对文件内容进行哈希计算(默认md5)，取前20位

6. **vite 和 webpack 在热更新上有啥区别?**
   - Vite：
     - 基于原生ES模块，无需打包
     - 热更新时只更新修改的模块
     - 速度快，毫秒级响应
   - Webpack：
     - 基于打包后的bundle
     - 热更新时需要重新编译相关模块
     - 大型项目热更新速度较慢

7. **package.json 里面 sideEffects 属性的作用是啥**
   - 标记模块是否有副作用
   - 帮助webpack等构建工具更好地进行tree-shaking
   - 取值：false(无副作用)、数组(指定有副作用的文件)
   - 优化打包体积，移除未引用但有副作用的代码

2. **如何通过设置失效时间清除本地存储的数据?**
   ```javascript
   // 存储带过期时间的数据
   function setStorageWithExpiry(key, value, expiryInMinutes) {
     const now = new Date();
     const item = {
       value: value,
       expiry: now.getTime() + expiryInMinutes * 60 * 1000
     };
     localStorage.setItem(key, JSON.stringify(item));
   }
   
   // 获取数据并检查是否过期
   function getStorageWithExpiry(key) {
     const itemStr = localStorage.getItem(key);
     if (!itemStr) return null;
     
     const item = JSON.parse(itemStr);
     const now = new Date();
     
     if (now.getTime() > item.expiry) {
       localStorage.removeItem(key);
       return null;
     }
     return item.value;
   }
   ```

3. **浏览器的存储有哪些**
   - Cookie：4KB左右，随请求发送，有过期时间
   - localStorage：5-10MB，永久存储，同源共享

   - IndexedDB：较大存储空间(通常几百MB)，异步操作，支持事务
   - Web SQL：已废弃，不推荐使用
   - Service Worker Cache：用于离线缓存

     ```javascript
     function isInViewport(element) {
       const rect = element.getBoundingClientRect();
       return (
         rect.top >= 0 &&
         rect.left >= 0 &&
         rect.bottom <= (window.innerHeight || document.documentElement.clientHeight) &&
         rect.right <= (window.innerWidth || document.documentElement.clientWidth)
       );
     }
     ```

## 安全与认证
1. **单点登录是什么，具体流程是什么**
   - 定义：一次登录，多系统访问
   - 流程：
     1. 用户访问系统A，未登录则跳转到SSO认证中心
     2. 用户在认证中心登录，生成令牌
     3. 认证中心跳转回系统A，并携带令牌
     4. 系统A验证令牌，验证通过则登录成功
     5. 用户访问系统B，跳转到认证中心
     6. 认证中心发现已登录，直接返回令牌给系统B
     7. 系统B验证令牌通过，登录成功

2. **OAuth2.0 是什么登录方式 单点登录是如何实现的? 常见的登录鉴权方式有哪些?**
   - OAuth2.0：第三方授权登录框架，允许应用获取用户在另一服务的有限权限
   - 常见登录鉴权方式：
     - 用户名密码登录
     - 验证码登录
     - 第三方登录(OAuth2.0)
     - 生物识别登录
     - Token认证(JWT)
     - Session-Cookie认证

3. **需要在跨域请求中携带另外一个域名下的 Cookie 该如何操作?**
   - 服务器端：设置Access-Control-Allow-Credentials: true
   - 客户端：请求时设置withCredentials: true
   - 确保Access-Control-Allow-Origin不是通配符*
   - 两个域名需满足Cookie的domain和path规则

4. **判断一个对象是否为空，包含了其原型链上是否有自定义数据或者方法。该如何判定?**
   ```javascript
   function isObjectEmpty(obj) {
     // 检查自身属性
     if (Object.keys(obj).length !== 0) return false;
     
     // 检查原型链
     let proto = Object.getPrototypeOf(obj);
     while (proto !== Object.prototype && proto !== null) {
       if (Object.keys(proto).length !== 0) return false;
       proto = Object.getPrototypeOf(proto);
     }
     return true;
   }
   ```

   ```javascript
     // 基本类型和引用同一对象的情况
     if (obj1 === obj2) return true;
     
     // 处理null情况
     if (obj1 === null || obj2 === null) return false;
     
     // 处理日期
     if (obj1 instanceof Date && obj2 instanceof Date) {
       return obj1.getTime() === obj2.getTime();
     }
     
     // 处理数组
     if (Array.isArray(obj1) && Array.isArray(obj2)) {
       if (obj1.length !== obj2.length) return false;
       return obj1.every((item, index) => deepEqual(item, obj2[index]));
     }
     
     // 处理对象
     if (typeof obj1 === 'object' && typeof obj2 === 'object') {
       const keys1 = Object.keys(obj1);
       const keys2 = Object.keys(obj2);
       
       if (keys1.length !== keys2.length) return false;
       
       return keys1.every(key => 
         keys2.includes(key) && deepEqual(obj1[key], obj2[key])
       );
     }
     
     return false;
   }
   ```

6. **JS 执行 100万个任务，如何保证浏览器不卡顿?**
   - 使用requestIdleCallback利用浏览器空闲时间执行
   - 分批次执行，配合setTimeout或setImmediate
   - 使用Web Worker在后台线程执行
   - 示例：
     ```javascript
     function processTasks(tasks, batchSize = 1000) {
       let index = 0;
       
       function processBatch() {
         const end = Math.min(index + batchSize, tasks.length);
         for (; index < end; index++) {
           // 处理单个任务
           tasks[index]();
         }
         
         if (index < tasks.length) {
           setTimeout(processBatch, 0); // 让出主线程
         }
       }
       
       processBatch();
     }
     ```

7. **一次性渲染十万条数据还能保证页面不卡顿**
   - 实现虚拟滚动(只渲染可视区域数据)
   - 分批次渲染，使用requestAnimationFrame
   - 示例虚拟滚动核心思路：
     ```javascript
     // 只渲染可视区域内的项
     function renderVisibleItems(container, items, itemHeight, visibleCount) {
       const scrollTop = container.scrollTop;
       const startIndex = Math.floor(scrollTop / itemHeight);
       const endIndex = Math.min(startIndex + visibleCount + 1, items.length);
       
       // 计算偏移量
       container.style.paddingTop = `${startIndex * itemHeight}px`;
       
       // 只渲染可见范围内的项
       const visibleItems = items.slice(startIndex, endIndex);
       renderItems(visibleItems);
     }
     ```
